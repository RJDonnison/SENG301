# SBI Framework

Used for **giving and receiving feedback** — especially in code reviews, 1:1s, and team retrospectives.

| Component     | Meaning                             | SWE Example                                                   |
| ------------- | ----------------------------------- | ------------------------------------------------------------- |
| **S**ituation | When/where it happened              | "In yesterday's PR review for the auth service..."            |
| **B**ehaviour | What you observed (not interpreted) | "...you merged without waiting for a second approval"         |
| **I**mpact    | Effect on team, product, or process | "...which pushed a bug to staging and blocked QA for 3 hours" |

## When to use

- Giving feedback in code reviews without making it personal
- 1:1s with teammates or reports
- Raising process issues in retrospectives

## Tips for SWEs

- **Behaviour must be observable** — describe what happened, not personality. Say "the PR was merged without review" not "you don't care about quality"
- Keep it **specific to one event** — don't stack historical grievances
- Follow up with a question: "What was your thinking there?" — opens dialogue rather than closing it
- Works equally well for **positive feedback**: "In the sprint demo (S), you walked the stakeholders through the edge cases (B), which gave them real confidence in the release (I)"
